# muse-city-lab — SENDAI Real-Data Scroll Prototype

「JAPAN — THE CITY COLLECTION」の実データ方式を検証する独立プロジェクトの公開用リポジトリ。
本編（Three.js プロシージャル方式、Hiro2821/japan-city-collection）とは別に、CesiumJS + 国土交通省 PLATEAU の実データで「スクロール連動のリアルタイム都市」がどこまで成立するかを試作・検証しています。

**公開ページ: https://hiro2821.github.io/muse-city-lab/**

## 試作の内容

- 仙台の実データ都市（PLATEAU 仙台市 3D都市モデル 2024年度・青葉区 LOD2 テクスチャ付き建物＋PLATEAU-Ortho 2023 航空写真＋国土地理院 DEM 地形）を CesiumJS で表示
- 実座標カメラルート: 仙台駅 → 青葉通 → 定禅寺通 → 一番町 → 青葉城址（広瀬川越しのフィナーレ）
- 駆動は本編と同じ決定論的スクロール制御: 600svh トラック、`p = clamp(-top/(trackH-stageH))`、`t = min(1, p/0.94) × 54`、逆スクロールで同じ p = 同じ構図

### URL パラメータ

| パラメータ | 値 | 意味 |
|---|---|---|
| `?route=` | `v1`（既定） / `v2` | v2 は青葉通・定禅寺通・一番町に高度 6〜8m の街路レベルキーを追加 |
| `?grade=` | `day` / `dusk`（既定） / `night` | 太陽時刻を正とした時間帯プリセット（12:00 / 17:20 / 19:30 JST） |
| `?renderer=` | `tileset` / `model` | 建物の読み方。無指定時の既定は通常 tileset / モバイル時は model（GLB 24枚、総量約78.7MBで固定）。**model は GLB ファイルのリポジトリ配置が別途必要**（下記「検証状況」参照） |
| `?terrain=` | `ellipsoid`（既定） / `dem` | dem は国土地理院 dem_png 地形を使用。モバイル時は dem を指定しても `?dem=force` がない限り ellipsoid に落ちる（クラッシュ回避優先） |
| `?dem=` | `force` | モバイルでも terrain=dem を強制する（切り分け検証専用） |
| `?heightfix=` | `on`（既定） / `off` | カメラ高度の基準面補正（基盤楕円体高 = DEM標高 + ジオイド 40.67m） |
| `?lights=` | `on` | 窓明かり点群の重ね物試作（本採用ではない到達度検証用） |
| `?mobile=` | `1` / `0` | iPhone 向け軽量プロファイル。無指定時は自動判定（タッチ主体＋小画面、または iOS のとき有効）。第2段（2026-11-22）: renderer 既定 model、DEM 抑制、SSE 48、resolutionScale 1.0、tileset キャッシュ 64MiB、同時リクエスト抑制 等 |
| `?sse=` | 数値 | 建物タイルの maximumScreenSpaceError の上書き（既定は通常 16 / 軽量時 48） |
| `?debug=` | `1` | p / t / タイル読み込み状態のデバッグ表示 |

注: `?tiles=proxy`（ローカル検証用プロキシ）は公開版では利用できません（ローカル検証環境専用）。

## 検証状況（2026-11-22、デスクトップ検証まで完了）

確認できたこと:

- 地表が描画されない問題を解決（原因は航空写真レイヤの `minimumLevel` 指定）
- カメラ高度の基準面ずれを補正し、街路レベル（対地 6〜8m）の構図が成立することを確認
- 地理院 DEM 地形で建物足元と地表の段差が構図内で見えなくなるところまで到達
- 夜は標準機能だけでは「灯りのない暗い街」止まりで、窓明かりは建物に整合した重ね物が別途必要と判明
- 転送量は初期表示で約14MB、通し表示では百MB級（内訳は PLATEAU 建物タイルが約85〜90%）。本編のバンドル約944KB とは桁が違う

iPhone 実機（2026-11-22、実機結果2件）:

- **1件目: `?route=v2&terrain=dem` を iPhone / Safari で開くと「問題が繰り返し起きました」（繰り返しクラッシュ）で表示できなかった**
- 第1段対策として軽量プロファイル（`?mobile=`、iPhone では自動適用）を実装: SSE 32、tileset キャッシュ 128MiB 上限、resolutionScale 1.5、DEM 33×33＋キャッシュ上限 24 枚。VM での定量比較では総転送量 −11%、DEM サンプリング量 −62% を確認（JS ヒープは VM では減少を確認できず）
- **2件目: 第1段対策後も「重すぎる」で実用不可**。タイル方式の実機成績は2回不合格となった
- 採否基準（Shibu 明言）: 合否は実在感ではなく「iPhone 実機でスクロールに追随して滑らかに動くこと」で決まる
- 第2段対策（実装・公開済み）: モバイルでは renderer 既定を GLB 方式（総量約78.7MBで固定、読み切り後の追加転送なし）に切替、DEM を既定オフ化、SSE 48・キャッシュ 64MiB・resolutionScale 1.0・同時リクエスト抑制を追加。VM のスクロール追随計測では、タイル方式はスイープ中 +42.6MB・停止後180秒でも未静定だったのに対し、GLB 方式はスイープ中の建物転送ゼロ・停止後 0.1 秒で静定した
- **未完了: GLB ファイル（`models/`、24枚・約78.7MB）のリポジトリ配置**。GitHub コネクタのファイル送信がテキスト専用のため自動配置できず、リポジトリ所有者による git push が必要。配置されるまでは公開版で GLB 方式は動かないが、コード側の安全弁で tileset へ自動フォールバックするため、モバイル既定でも建物が出ない状態にはならない。GLB 方式の iPhone 実機での滑らかさは未検証で、確認できない場合は実データ方式は仙台のスクロール本編には不採用が妥当という結論方向を記録済み（詳細は検証リポジトリ側 README と docs/COMPARISON.md）

未検証:

- フィナーレで白い無テクスチャ建物が多い理由（LOD選択か区域的な LOD1 のみ収録か）

本編との比較表は [docs/COMPARISON.md](docs/COMPARISON.md) にあります。

## データ出典

- 国土交通省 Project PLATEAU — 仙台市 3D都市モデル（2024年度・青葉区 LOD2）/ PLATEAU-Ortho 2023
- 国土地理院 標高タイル（dem_png）
- PLATEAU のコンテンツは公共データ利用規約（PDL1.0、CC BY 4.0 互換）に基づき利用しています。`models/` の建物 GLB は、PLATEAU の 3D Tiles データを加工（抽出・変換）して作成したものです

## 配信方法について

Cesium 本体はリポジトリに含めず、jsDelivr CDN（cesium@1.124.0）から読み込んでいます。PLATEAU 等のタイルは各配信元から直接読み込みます。
